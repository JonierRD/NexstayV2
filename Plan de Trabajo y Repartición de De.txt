Módulos de Frontend que Faltan por Crear y Desarrollar
Módulo	Estado en Backend	Lo que falta construir en Frontend
1. Dashboard General	Datos dispersos en varias tablas	Vista ejecutiva: tarjetas de KPI (ocupación %, habitaciones libres/ocupadas, ingresos del día, check-ins/check-outs previstos hoy) y accesos directos rápidos.
2. Directorio de Clientes	
clientes.controller.ts
 listo	Tabla con buscador por cédula/nombre/teléfono, modal de creación/edición de cliente y modal con historial de hospedajes anteriores del cliente.
3. Huéspedes Activos	
stays.controller.ts
 listo	Vista tipo tarjetas o tabla de todos los huéspedes actualmente alojados, consumos extra cargados a su cuenta, días transcurridos y botón directo de Check-Out.
4. Inventario / Stock	
inventory.controller.ts
 listo	Catálogo de productos, control de stock disponible vs stock mínimo (alertas en rojo), modal para ajuste rápido de existencias (+ / -) y creación de nuevos productos.
5. Ventas / Tienda (POS)	Sale y Payment en Prisma	Punto de venta ágil para recepcionistas: registrar venta de productos (al contado o cargado a una habitación/hospedaje activo) y registro de abonos.
6. Lavandería	
laundry.controller.ts
 listo	Panel kanban o tabla con filtros de prendas por estado (PENDIENTE, EN_PROCESO, LISTO, ENTREGADO), registro de orden de lavado, cobro y vinculación con habitación.
7. Parqueadero	Tablas MonthlyParking / ParkingPayment en Prisma	Registro de vehículos (mensual y por días), control de pagos por mes (1-12) y semáforo de morosidad por placa.
8. Turnos y Caja / Perfil	Tabla Shift en Prisma	Registro de apertura y cierre de turno de recepcionista con arqueo de base de dinero, novedades y firmas. Pantalla de perfil de usuario para cambio de contraseña.
2. Requisitos de Entorno y Configuración para los Desarrolladores
Para que cualquier miembro del equipo pueda clonar y levantar el proyecto sin errores, deben tener la siguiente configuración:

Requisitos de Software
Node.js: Versión 22.x LTS o superior (node -v).
npm: Versión 10.x o superior (npm -v).
PostgreSQL: PostgreSQL 16+ corriendo localmente en el puerto 5432 (o contenedor Docker).
Git: Instalado y configurado con nombre y correo (git config user.name, git config user.email).
Editor: Visual Studio Code con las extensiones recomendadas:
Tailwind CSS IntelliSense
Prisma
ESLint y Prettier
Guía de Primer Arranque para cada Desarrollador
bash


# 1. Clonar el repositorio
git clone <URL_DEL_REPOSITORIO>
cd NexstayV2
# 2. Configurar variables de entorno
cp .env.example .env
# Ajustar DATABASE_URL en .env si la contraseña de PostgreSQL local difiere
# 3. Instalar dependencias del monorepo
npm install
# 4. Generar el cliente de Prisma y sincronizar tablas
npm run prisma:generate
npm run prisma:push
# 5. Iniciar API y Escritorio concurrentemente
npm run dev
# API responderá en http://localhost:3333
# Renderer Vite en http://localhost:5173

Reglas de Oro del Repositorio
Ramas Protegidas:
main: Producción estable. Nadie sube cambios directos (push deshabilitado).
develop: Rama de integración donde se unen las características terminadas.
Nomenclatura de Ramas:
feat/clientes-ui (Nueva funcionalidad)
feat/inventario-pos
feat/lavanderia-modulo
fix/ajuste-calculo-noches (Corrección de error)
Flujo de Trabajo Diario:
bash


# Al iniciar el día:
git checkout develop
git pull origin develop
git checkout mi-rama
git merge develop
Pull Requests (PR):
Todo PR debe apuntar a develop.
Requiere revisión y aprobación de al menos 1 desarrollador (o el Lead) antes del merge.
Prohibido hacer git push --force en ramas compartidas.
4. Patrones de Código y Arquitectura Frontend que Deben Respetarse
Para mantener el diseño y comportamiento idéntico al código ya programado:

1. Sistema de Diseño y Paleta de Colores (Tailwind CSS)
Utilizar la paleta temática del hotel ya definida en 
RecepcionPage.tsx
 y 
HabitacionesPage.tsx
:

Fondo Principal: bg-[#f6f1eb] o bg-[#fbf8f4]
Tarjetas: bg-white border border-[#eadfd6] rounded-[20px] shadow-[0_16px_40px_rgba(67,42,27,0.08)]
Botones Primarios: bg-[#4b2b21] hover:bg-[#5a3429] text-white rounded-xl
Botones Secundarios: bg-white border border-[#dccfca] text-[#4b2b21] hover:bg-[#faf6f2]
Estados / Badges:
Verde (Éxito / Disponible / Pagado): bg-[#e9f6eb] text-[#2f8f4e] border-[#c6e8cf]
Rojo (Ocupado / Pendiente / Deuda): bg-[#fff0ee] text-[#c94a43] border-[#f0c8c4]
Amarillo (Reservado / En Proceso): bg-[#fff5df] text-[#c78b14] border-[#f2dbab]
2. Capa de Conexión a la API (
lib/api.ts
)
NO usar fetch directo en los componentes React.
Agregar funciones exportadas en 
lib/api.ts
 usando apiRequest<T>(), que automáticamente inyecta el token JWT y maneja errores.
3. Reutilización de Modales de Seguridad
Si una acción requiere confirmación: Usar ConfirmModal (
ConfirmModal.tsx
).
Si una acción crítica requiere permiso de Administrador: Usar AdminPasswordModal (
AdminPasswordModal.tsx
).
